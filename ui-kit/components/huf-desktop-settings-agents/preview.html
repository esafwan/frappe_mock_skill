Agents and permissions

What agents may do on this computer.What agents may do on this computer. Start with the approval mode in the chat composer; use this page for per-agent limits and for remote control. Everything here applies to the workspace you have open.

Approval mode

How agent actions are approved is set per workspace, from the Permissions chip in the chat composer. It decides what runs freely and what asks you first.Change the mode from the Permissions chip in the chat composer. Each workspace keeps its own mode, and Ask every time is the starting point for a new one.
Ask every time
Every write, delete and command asks for approval, every time. Reads run freely.
Auto
Reads run freely. Writes and commands ask; you can allow a kind of action for the rest of the run. Deletes and protected paths always ask.
Sandboxed
Reads and normal writes inside the workspace run freely. Commands run confined to the workspace and ask first. Sensitive or protected paths ask.
Full access
No gating. Every operation runs immediately, commands run unconfined.

Limits per agent

Turn a kind of access off, or force a prompt, for one agent or for every agent in this workspace. Limits can only tighten what the approval mode allows; the Huf server can also set a ceiling for an agent, and the stricter of the two applies.
off
The agent is refused, whatever the approval mode says.
ask
The agent always prompts you, even where the mode would let it run.
allowed
No extra limit; the workspace approval mode decides.
Areas: cli (commands), files, skills, local_mcp (local MCP servers), browser, installs (package installs) and processes (long-running background commands).
5 limits

For workspace supplier-ops. Off refuses, Ask always prompts, Allowed follows the workspace permission mode. The most restrictive setting wins.

  • Workspace default - cli: ask
  • Workspace default - files: allowed
  • Workspace default - installs: ask
  • Buying Assistant - cli: off
  • Buying Assistant - browser: off

Making something more permissive asks for confirmation in a system dialog.

Remote control

Lets your Huf web and mobile sessions use this computer's tools. It is off by default and worth leaving off unless you actually work from another device.Off
Turn it on to let your Huf web and mobile sessions use this computer, each workspace under its own approval mode. A system dialog asks you to confirm.

Risk. While on, remote sessions use each workspace's own permission mode with no extra prompt and can change that mode, including to Full. Anyone who controls your signed-in Huf session can therefore act here. Every remote call and mode change appears in Activity.

Some packages run a script when installed. Off, they do not. Turn it on only if a project you trust needs them. It applies to the open workspace only.
